# 接口

`POST /api/run`：JSON中的csv文本，省略使用样例；或multipart字段file。最大5MB。

`POST /api/m1`至`POST /api/m8`：独立运行到指定模块，JSON结构同运行接口。

`GET /api/history`：历史批次。`POST /api/review`接收id、revision和decision（通过或退回），通过时把该批次的客户分摊结果写入已确认台账；对同一账户的归属变更须附带`acknowledge`字符串数组显式确认，否则409。`GET /api/publish`返回客户权益发布状态（可发布/待复核/已发布/不可发布、客户总数、与已确认差异、阻断项）。`GET /api/evidence.csv`提供单一证据导出。

结构错误422，版本变化409，文件过大413；错误返回code与message。所有页面可从左侧八个模块入口访问。

`GET /api/runs/<id>`读取指定批次；页面与证据CSV通过run_id查询参数绑定批次，模块导航保留该参数。

JSON请求体必须是对象，数组、标量、null、损坏JSON及错误上传字段返回400，且不运行默认样例。

输入表头必须包含全部必填列，另可包含可选归属列`client`与`account`（顺序任意）。旧样例不含这两列时，账户默认等于持仓记录、客户默认等于账户。

## 复核与发布

- 复核使用revision乐观锁；同一revision仅允许一次复核，陈旧提交409。
- 当前已确认批次不能再退回（409），只能提交新批次复核覆盖。
- 通过复核时若`publish`存在阻断项（归属冲突、记录不守恒、分摊不闭合），返回409 `PUBLISH`，不写入台账。
- 已确认台账以`账户 × 证券 × 除权日`为业务主键；台账按run_id整表替换而非累加，同一批次重复提交复用原批次，不重复增加权益。
- 晚到批次只与已确认台账比对，生成差异列表；不改写已确认结果，也不会因为重跑而改变已确认台账。
- 若晚到记录把已确认账户改挂到另一客户，发布状态为“不可发布”，必须在复核请求中逐账户列出`ATTRIBUTION_CHANGED:<账户>`确认后才可通过。
